# Technical decision register

| ID | Decision | Alternatives considered | Rationale | Consequence |
|---|---|---|---|---|
| D-01 | DuckDB as engine | pandas chunks, Polars (not installed) | correct multi-line quoted CSV parsing; out-of-core SQL; GROUPING SETS give split validation in one pass | single dependency for L1–L5 |
| D-02 | Parquet (zstd) intermediates | DuckDB database file | the database file ran out of disk (4.8 GB free); Parquet is 1.27 GB + 0.48 GB | the slim table holds no free text; text rules read payments.parquet |
| D-03 | Drop DISCLAIMER from analytic tables | keep the column | non-empty on exactly 1 row (legal notice), no analytic content | documented in the issues log |
| D-04 | Accept rules on effect size and exactness | p-value thresholds | n = 10M makes every non-zero difference significant | criteria stated per validator |
| D-05 | Five-split validation (full, 2 hash halves, 2 periods) | k-fold | rules are population statements; halves test chance, periods test stability | every rule reports per-split metrics |
| D-06 | Bank speed classes learned on half 0, tested on half 1 | in-sample classes | avoids circularity in D1 | out-of-sample additivity 1.89 |
| D-07 | Two-way fixed-effect demeaning for D2 | logit with crossed random effects | transparent, linear-time on 4M rows; enough to expose the Simpson effect | linear-probability approximation disclosed |
| D-08 | Home-currency map inferred from data (modal currency of sending country) | external ISO country→currency table | external primary data not allowed (RR 2.3); C2 validates the map at 99.99998% | 2 unmapped rows |
| D-09 | Time-zone offsets estimated from activity profiles | tz database | external data avoided; the estimate revealed the January (no-DST) artefact | whole-hour precision |
| D-10 | No ML classifiers | gradient boosting on labels | the task is rule reconstruction; label-fitting accuracy would not prove generation rules; rule detectors evaluated per class | one GaussianMixture (density estimation, X3) |
| D-11 | No NetworkX | install NetworkX | not installed; PageRank via SciPy sparse power iteration is about 20 lines and fast on 8.7k nodes / 2.3M edges | no extra dependency |
| D-12 | Streamlit + Altair (bundled) | Plotly (not installed), Dash, custom React | already installed; locally reliable; AppTest gives headless functional tests | neo-brutalist theme via CSS |
| D-13 | PDFs by HTML + Edge headless | matplotlib-only PDFs, PowerPoint | identical typography to the app; page limits assertable | requires Edge or Chrome on the build machine |
| D-14 | Product name **The Synthetic Rule Intelligence Lab** (earlier RULEBOOK/10M) | "Swift Intelligence Lab" | names the task (rule reconstruction), avoids implying Swift endorsement | the case is cited as "Swift case study" only |
| D-15 | Local system fonts (Bahnschrift, Segoe UI, Consolas) | Google Fonts | offline-safe for the app and the PDF build; Bahnschrift's condensed geometric face fits the neo-brutalist look | no pixel font; the retro accent comes from monospace labels and blocky shadows |
| D-16 | Aggregated route patterns (country sequences, n ≥ 200) instead of raw example routes | ship sample rows | dataset is organiser IP (RR 2.2); aggregates give the same insight | Route Explorer works on patterns |
| D-17 | Graph and stats outputs read by validators G1/D3 | recompute inside validators | keeps the validation loop fast; outputs regenerated by run_all before validation | ordering enforced in run_all.py |
| D-18 | Discovery engine = pair scan + depth-3 trees, holdout-scored | Apriori association rules | tree leaves give the same IF-THEN form; mlxtend not installed | trees are a search device only |
| D-19 | Mediation triage by stratified Cramér's V (one/two mediators, 'Other' stratum excluded) | partial correlation | categorical data; interpretable; residual V threshold 0.03 disclosed | 13 pairs classed as composites |
| D-20 | Change points by binary segmentation with BIC penalty | PELT library (not installed) | 91 points; exact search is cheap | located T4b |
| D-21 | No Bayesian layer, no GPD/EVT fit | PyMC, scipy genpareto | Beta posteriors = Wilson CIs at n=10M; A3 already characterises the tail | documented in feature_justification.md |
| D-22 | Web platform rebuilt as vanilla ES modules with a hash router and an in-house SVG chart kit | React/Vite + a chart library | no build step on Vercel, no third-party scripts (CSP `script-src 'self'`), ~9 MB total, every module testable in the browser | `web/app/`, `docs/defect_register.md` |
| D-23 | Browser explorer runs on an additive 10-dimension cube with binned amount/duration histograms (10,396 cells) | ship a row sample; server-side queries | exact counts, sums, means and CIs for any filter combination; no row-level data leaves the pipeline; medians/KS are bin-resolution (disclosed on the page) | `src/webdata.py`, `test_explorer_matches_python…` |
| D-24 | Six-level confidence scale (VALIDATED … REJECTED) with criteria fixed in advance; rejected hypotheses kept as registry entries | High/Medium/Low only | separates "exact on every row" from "passes with inferred mechanism" and makes negative results visible | `registry.json → levels`, Approach page |
| D-25 | Benjamini–Hochberg applied within each test family on the site's test registry | BH pooled over all 287 p-values | pooling lets a weak test borrow strength from thousands of near-zero p-values (it made X5 look significant) | `test_bh_is_per_family` |
| D-26 | Simulator uses the stats.py structural amount model (6 + 2·[S=B] + 2·[R=B] + country effect, residual sd 2.08) and a cover mixture solved to reproduce the pooled share | A1 cell intercepts + country effects | avoids double-counting the intercept; model already validated by the exceedance check | `web/app/js/sim.js` |
| D-27 | Browser E2E tests drive the system's Microsoft Edge through Playwright | download Playwright's Chromium | no 150 MB browser download; Edge is present on every Windows judge machine | `tests/test_web_e2e.py` |
| D-28 | No server-side query API; Forensic Replay ships exact counts + bounded de-identified samples | FastAPI / serverless DuckDB over Parquet | static Vercel hosting cannot hold the 0.48 GB Parquet; a public row-level endpoint would breach rules 2.1–2.2; exact counts need no server | `src/replay.py`, `docs/DATA_PIPELINE.md` |
| D-29 | Rule genealogy built only from the logged hypothesis order (H1–H37) | reconstruct a narrative history for every rule | the brief forbids manufactured history; 6 rules without a log entry say so | `src/ledger.py` |
| D-30 | Kept the existing vanilla ES-module front end rather than migrating to Next.js | Next.js/React rewrite | working, tested product; a rewrite adds risk five days before the deadline with no analytical gain | `docs/PROJECT_RECONNAISSANCE.md` |
